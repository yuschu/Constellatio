# 插件开发文档：v1.5.18 审批人限定业务负责人 + 抄送直系领导

> 关联插件：approval（动态表单 / 路由 / 抄送）
> 版本：v1.5.18 · 文档日期：2026-10-23
> 状态：**✅ 已实现**（184 项测试全绿 + Docker 重建 + 冒烟）

## 一、需求

1. **审批人选项范围限定相关业务负责人**（不再列出全员）；
2. **抄送直系领导**（申请人的直属上级）；
3. **去掉审批人留空**（必选）。

## 二、设计口径（契约）

| 项 | 决策 |
|---|---|
| 审批人候选 | `routing.candidate_approvers(type)`：管辖部门内经理角色 → 该部门内具备 `approval_approve` 的启用用户；即「相关业务负责人」 |
| 无路由部门时 | 回退：申请人直属上级 + 具备 `approval_approve` 的启用用户（去重、排除申请人） |
| 表单字段 | 审批人 `required=True`，选择项**不含留空项**；默认选中候选第一位；帮助文案说明限定范围 |
| 提交校验 | 只接受候选内 id（ChoiceField 校验）+ 服务端再查启用用户；无效报「请选择有效的业务负责人」 |
| 抄送 | 改为抄送**申请人直系领导**（`applicant.leader`）；若其就是申请人或审批人则跳过；发起、通过、驳回时幂等补齐 |
| 旧规则 | 不再抄送「审批人的上级」；`services._cc_approver_superior` 改为 `_cc_applicant_leader` |
| 数据 | 无新表、无迁移 |

## 三、测试

- 表单：审批人下拉不含留空项；只出现候选负责人；必选校验；
- 路由：报销候选=财务经理、请假候选=HR 经理（原路由测试改为选择负责人）；
- 抄送：申请人直系领导进入 `cc_users`，审批完成仍保留；领导=审批人时不重复；
- 守卫/重申请/终态/空项等既有用例调整后不回归；
- 全量 184 项通过。
