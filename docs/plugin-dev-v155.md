# v1.5.5：审批动态表单 + 考勤筛选 + 工作台 + 交互增强

> 关联插件：approval（动态表单 / 抄送）、attendance（状态 / 类型 / 筛选 / 补卡）、user（直属上级 / 密码权限）、plugin_host（菜单高亮 / 工作台）、structure（上级映射）
> 版本：v1.5.5 · 文档版本：v1.0 · 2026-10-22
> 状态：**✅ 已实现**（138 项测试全绿；Docker 部署供负责人验收）

## 一、需求明细

1. 侧边栏菜单高亮当前选中 Tab。
2. 密码修改权限：仅超级管理员本人与该账号所属用户可修改，其他角色无权限。
3. 审批发起动态表单（选择类型渲染对应输入项，`*` 为必填）：
   - 请假：时间* / 事由 / 部门* / 审批人
   - 报销：提交时间* / 费用事由 / 部门* / 审批人
   - 用章：申请用章时间* / 用章文件及用途 / 部门* / 审批人
   - 外出：外出起止时间* / 外出事由 / 部门* / 审批人
   - 加班：加班起止时间* / 加班事由 / 部门* / 审批人
   - 调休：调休时间* / 调休依据*（关联加班记录）/ 部门* / 审批人
   - 流转：审批人收到申请自动抄送其上级；完成后结果同步申请人，并抄送审批人上级。
4. 签到详情筛选：签到时间范围（起止日期 + 时间）、签到状态（正常 / 迟到 / 早退 / 缺卡 / 补卡）、签到类型（内勤 / 外勤）。
5. 工作台作为默认首页，待办优先、插件运维下沉，区分管理员视图与员工视图。

## 二、实现

### 2.1 侧边栏高亮

- `plugin_host/context_processors.py` 为每个菜单计算 `active`：精确命中优先；详情页按路径前缀归属父菜单；同一前缀下只高亮最精确项（避免「考勤打卡」和「签到详情」同时亮）。
- 两套主题的 `base.html` 输出 `is-active` 与 `aria-current="page"`；Corporate Clean / Risograph 各补 `.is-active` 样式（蓝色左侧条 / 套印底纹）。

### 2.2 密码修改权限

- `UserForm.can_change_password`：`operator.is_superuser` 或 `operator == 目标账号` 才渲染密码字段。
- 其他操作者（含 `user_manage` 管理员）表单不出现密码字段，提交的密码值被忽略；新建用户使用默认密码 `constellatio123`。
- 个人中心改密仍要求旧密码校验（账号本人）；超管在用户编辑页可为任意账号设置新密码。

### 2.3 审批动态表单与抄送

模型（`approval.0004`）：

| 字段 | 说明 |
|---|---|
| `form_data` JSON | 各类型动态字段值（含 `basis` / `basis_label`） |
| `department_id` / `department_name` | 表单部门快照（跨插件零 import） |
| `approver` 可空 | 留空时按「直属上级 → 启用超管」兜底 |
| `cc_users` M2M | 抄送人（审批人上级） |

- `Type` 新增 `outing` / `overtime` / `comp`。
- `user.User` 新增 `leader`（直属上级，`user.0005`）；`structure.LEADER_OF` 定义 31 个模板账号的汇报关系，`apply_structure` 与 `manage.py grant_role_perms --seed-leaders` 只补空、不覆盖人工调整。
- `plugins/approval/forms.py`：六个类型表单 + 公共「部门* / 审批人（可留空）」，类型 Tab 服务端切换（`?type=`），必填项渲染 `*`。
- 提交：部门快照、`title = 类型｜姓名`、`content` 摘要、`form_data` 原始值；`services.submit` 抄送审批人上级。
- 审批完成：`approve/reject` 再次幂等抄送审批人上级；申请人通过「审批中心 / 详情」看到结果；审批人上级在「抄送我的」查看。
- 调休依据：只列出本人未被驳回的加班审批；无加班记录时禁用并提示先发起加班审批。

### 2.4 签到状态 / 类型 / 筛选 / 补卡

模型（`attendance.0003` + 回填 `0004`）：

| 字段 | 取值 |
|---|---|
| `sign_type` | `internal` 内勤签到 / `external` 外勤签到 |
| `is_makeup` | 是否补卡 |
| `status` | `normal` / `late` / `early` / `missing` / `makeup` |

状态推导（`Attendance.compute_status`，保存时计算）：
补卡 → 缺卡（无签到）→ 迟到（签到晚于 09:00）→ 早退（签退早于 18:00）→ 正常。

- 打卡页增加签到类型选择；签到详情筛选：起止时间（`datetime-local`）、状态、类型、部门、姓名。
- 补卡登记（`attendance_report_view`）：选择员工 / 日期 / 起止时间 / 类型，写入 `is_makeup=True`，状态标记补卡。

### 2.5 工作台

`plugin_host/views.py` 注入：待我审批数、今日考勤状态、快捷入口、公告前 3 条、启用插件统计。

| 顺序 | 模块 | 管理员 | 员工 |
|---|---|---|---|
| 1 | 待办聚合（待我审批 / 考勤待处理） | ✓ | ✓ |
| 2 | 流程快捷发起（请假 / 报销 / 用章 / 外出 / 加班 / 调休 / 签到详情） | ✓ | ✓（无签到详情权限时显示「我的考勤」） |
| 3 | 插件运维（架构 / 已启用统计 / 开关入口） | ✓ | 不渲染 |
| 4 | 公告简报（最新 3 条 + 全部入口） | ✓ | ✓ |

- 管理员视图判定：超管或 `workspace_manage`；顶部显示「管理员视图 / 员工视图」。
- 待办数 = 待我审批普通单 + 我会签未签；考勤状态 = 今日未签到 / 未签退 / 已完成。

## 四、边界

- 「结果同步申请人」以审批状态 + 详情页呈现，不新增站内消息中心；后续如需红点/消息可加通知模型。
- 审批人上级由 `leader` 字段确定；未设置上级时无抄送，不阻断审批。
- 补卡不改变原打卡时间口径，仅作为状态标记与补录。
- 签到详情仍为管理岗权限（`attendance_report_view`），员工在工作台看到「我的考勤」入口。

## 五、v1.5.14 增补：报销金额与用章附件

- 报销：新增「金额*」（`DecimalField`，2 位小数、≥0），落库 `Approval.amount` 并写入 `form_data['amount']`。
- 用章：原「用章文件及用途」拆为「用章文件*」（附件上传）与「用途」；附件存 `Approval.attachment`，`MEDIA_ROOT/media/approval_attachments/%Y/%m/`。
- 附件限制：pdf/doc/docx/xls/xlsx/png/jpg/jpeg，单文件 ≤10MB；`.exe` 等被拒。
- 下载：`/plugins/approval/<id>/attachment/`，申请人/审批人/会签人/抄送人/`approval_view` 可下载，其余 302。
- 表单改 `multipart/form-data`；compose 增加 `media_data` 卷持久化附件。

## 六、v1.5.15 增补：审批路由与用章盖章占位

- **L3 隐藏待我审批**：菜单 / 视图 / 工作台卡片均改为 `approval_approve`；L3 仍可用审批中心与抄送我的。
- **调休时间段**：改为「调休开始时间* / 调休结束时间*」，结束须晚于开始。
- **管辖部门路由**（`routing.py`）：请假/外出/加班/调休 → 人力资源部；报销 → 财务部；用章 → 行政部；优先取部门经理角色，其次部门内具备 `approval_approve` 的用户；缺失时回退手动审批人 / 直属上级 / 超管。
- **电子盖章占位**（`eseal.py`）：用章通过后写入 `form_data.e_seal` 占位文本并记录 `e_seal` 流转；详情显示「电子盖章 · 待接入」，真实电子章插件接入时只替换 `apply_e_seal`。
- **信息提醒插件**：开发计划见 `docs/plugin-dev-notify.md`（v1.15）。
